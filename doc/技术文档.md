# Passformer: 基于多阶段学习的 LLVM 编译优化序列生成

## 1 概述

利用深度学习自动生成 LLVM 编译器优化 Pass 序列，超越 -O3/-Oz 等固定优化策略

采用三阶段渐进式训练范式，无监督预训练 → 监督序列生成 → 强化学习在线优化

## 2 阶段一：无监督语义表征学习（InstBERT）

### 2.1 动机与目标

编译器中间表示（Intermediate Representation, IR）是连接高级语言语义与底层机器指令的核心抽象层。LLVM IR 作为当前使用最广泛的编译器 IR 之一，承载了丰富的程序结构与语义信息——包括控制流、数据依赖、类型系统以及内存模型等。然而，传统的编译优化方法依赖手工设计的启发式规则或固定的优化 Pass 序列（如 `-O3`、`-Oz`），难以根据程序的个体特征进行自适应调整。

为使深度学习模型能够理解和推理 LLVM IR 的语义，首先需要为其构建高质量的分布式表征。然而，LLVM IR 与自然语言存在本质差异：其词汇表由编译器指令（如 `alloca`、`getelementptr`、`phi`）、类型标注（如 `i32`、`float*`）和结构化标识符构成，具有严格的形式化语法和操作语义。因此，直接复用面向自然语言的预训练模型及其 tokenizer 不仅会引入大量 out-of-vocabulary (OOV) 问题，还会破坏指令级别的语义完整性。

本阶段的目标是：**在大规模 LLVM IR 语料上，通过无监督预训练学习一个面向编译器指令的上下文相关语义表征模型（InstBERT）**，作为下游编译优化序列生成任务的 encoder 初始化。

### 2.2 模型架构

#### 2.2.1 基座模型：ModernBERT-base

选用 ModernBERT-base 作为 InstBERT 的基座架构。ModernBERT 相较于经典 BERT 引入了以下改进：旋转位置编码（RoPE）替代绝对位置编码以增强长序列外推能力、交替使用全局注意力与局部滑动窗口注意力（Global-Local Alternating Attention）以降低计算复杂度、GeGLU 激活函数替代 GELU 以提升表达能力，以及移除 token type embeddings 等冗余组件。这些设计使其在保持与 BERT 相当的参数规模（约 149M 参数）的同时，在长文本建模和训练效率上具有显著优势——这对于通常包含数百至数千条指令的 LLVM IR 程序尤为重要。

#### 2.2.2 Inst2VecTokenizer：面向 LLVM IR 的指令级分词器

与自然语言 tokenizer（如 BPE、WordPiece）不同，设计了专门面向 LLVM IR 的指令级分词器 `Inst2VecTokenizer`。其核心预处理流程基于 inst2vec（Ben-Nun et al., NeurIPS 2018, ETH Zurich）的 LLVM IR 规范化方案，主要包括以下步骤：

1. **结构体类型内联（Struct Type Inlining）**：将 LLVM IR 中的命名结构体类型（如 `%struct.foo`）替换为其完整定义，消除跨作用域的类型别名依赖。
2. **指令级规范化（Statement-level Normalization）**：对每条 LLVM IR 指令执行正则化处理，包括变量名匿名化（将 `%var_name` 归一化为占位符）、常量折叠、元数据标签去除等，以提取指令的核心操作语义。
3. **无效行过滤**：去除注释行、空行、模块级元数据等不携带程序语义的内容。

经过上述预处理，每条 LLVM IR 指令被映射为词汇表中的一个 token。词汇表采用 pickle 格式序列化存储，包含全部 LLVM IR 规范化指令及 5 个特殊 token：`<pad>`（填充）、`<unk>`（未知）、`<bos>`（序列起始，兼作 `[CLS]`）、`<eos>`（序列结束，兼作 `[SEP]`）、`<mask>`（掩码）。

这种指令级分词策略的核心优势在于：**每个 token 恰好对应一条完整的 LLVM IR 语句**，保留了编译器中间表示的最小语义单元，避免了 subword tokenizer 将指令碎片化导致的语义损失。

#### 2.2.3 Embedding 层适配

由于 Inst2VecTokenizer 的词汇表大小与 ModernBERT 原始词汇表不一致，在模型加载后执行以下适配操作：

1. 调用 `model.resize_token_embeddings(len(tokenizer))` 对 embedding 矩阵及 LM head 的输出层进行 resize，新增 token 的嵌入向量以标准正态分布随机初始化。
2. 将 tokenizer 定义的特殊 token ID 同步写入模型配置（`pad_token_id`、`bos_token_id`、`eos_token_id` 等），确保模型在推理、生成和损失计算中正确处理特殊 token。

### 2.3 预训练方案

#### 2.3.1 预训练任务：Masked Language Modeling (MLM)

采用标准的掩码语言模型（Masked Language Model, MLM）作为预训练目标。在每个训练样本中，以概率 $p_{\text{mask}} = 0.3$ 随机选取 token 进行掩码处理，模型的训练目标是根据上下文预测被掩码位置的原始 token。

相较于 BERT 原始论文中 $p_{\text{mask}} = 0.15$ 的设定，将掩码比例提高至 0.3。这一选择基于以下考量：LLVM IR 程序中存在大量重复或半重复的指令模式（如连续的 `load`/`store` 序列、循环体中的 `phi`/`br` 模式），较低的掩码比例可能使模型过度依赖局部模式匹配而非深层语义理解。更高的掩码比例迫使模型捕获更长距离的上下文依赖和指令间的结构化关系。

数据整理（data collation）使用 HuggingFace 提供的 `DataCollatorForLanguageModeling`，并设置 `pad_to_multiple_of=8` 以利用 GPU tensor core 的对齐优化。

#### 2.3.2 数据集：POJ-104

预训练语料来自 POJ-104 数据集（Mou et al., AAAI 2016），该数据集原始收集自北大在线判题系统（Peking Online Judge），包含 104 个编程问题类别下的 C/C++ 源代码。使用经 Clang 前端编译后的 LLVM IR 版本，每个样本对应一个完整程序的未优化 LLVM IR 表示。数据集字段中 `llvm` 列存储 IR 文本，`label` 列存储问题类别标签（预训练阶段不使用标签列）。

数据集使用 HuggingFace `datasets` 库的 `load_from_disk` 接口加载，tokenization 阶段采用 32 进程并行处理以加速大规模数据预处理。

#### 2.3.3 训练超参数

的 InstBERT 预训练采用以下超参数配置：

| 超参数 | 取值 | 说明 |
|--------|------|------|
| 最大序列长度 | 512 | 每个样本最多 512 条 LLVM IR 指令 |
| MLM 掩码比例 | 0.3 | 高于标准 BERT 的 0.15，适应 IR 的重复性结构 |
| 训练轮数 | 10 | - |
| 单卡训练 batch size | 32 | - |
| 梯度累积步数 | 2 | 有效 batch size = 64 |
| 学习率 | 5×10⁻⁵ | AdamW 优化器 |
| 学习率预热步数 | 500 | 线性 warmup |
| 权重衰减 | 0.01 | - |
| 评估策略 | 每 epoch | 在测试集上评估 MLM loss |
| 模型保存策略 | 每 epoch，保留最优 2 个 | 基于 eval loss 选择 |
| 日志记录 | 每 100 步 | TensorBoard 可视化 |

训练框架基于 HuggingFace `Trainer` API，支持自动混合精度（AMP）、分布式数据并行（DDP）以及梯度检查点等加速策略。训练完成后，最终模型及 tokenizer 保存至 `final_model` 目录，供下游 Passformer 模型加载使用。

### 2.4 技术亮点与创新性分析

**（1）将现代 Transformer 架构引入 LLVM IR 表征学习。** 现有工作多采用经典 BERT 或 LSTM 架构处理 LLVM IR（如 ProGraML、CompilerGym 中的基线模型）。首次将 ModernBERT 架构应用于编译器 IR 领域，其 RoPE 位置编码和全局-局部交替注意力机制天然适合长序列 LLVM IR 程序的建模需求。

**（2）指令级分词器设计保留编译器语义原子性。** 不同于将 LLVM IR 视为普通文本并使用 subword tokenization 的方案（如 CodeBERT 等），Inst2VecTokenizer 基于 inst2vec 的规范化流程确保每个 token 对应一条完整的编译器指令。这种设计从根本上避免了 subword 分割破坏指令语义的问题，同时通过结构体内联和变量匿名化实现了跨程序的词汇表一致性。

**（3）较高掩码比例适配编译器 IR 的结构特征。** LLVM IR 相较于自然语言具有更强的局部规律性和模式重复性。实验性地将 MLM 掩码比例从标准的 0.15 提升至 0.3，促使模型学习更深层的上下文依赖而非表面模式匹配，为下游任务提供更具判别力的表征。

**（4）渐进式预训练为多阶段学习奠定基础。** InstBERT 的预训练权重将直接作为第二阶段 Passformer 编码器的初始化，实现知识从无监督 IR 理解到有监督序列生成的迁移。这种 "pretrain-then-finetune" 范式已在 NLP 领域被广泛验证，将其系统性地引入编译优化领域。

## 3 阶段二：编译优化序列监督学习（Passformer）


### 3.1 问题建模

编译优化序列生成可自然地建模为条件序列生成（conditional sequence generation）问题：给定一段未优化的 LLVM IR 程序 $\mathbf{x} = (x_1, x_2, \dots, x_n)$ 以及其对应的程序静态特征向量 $\mathbf{a} \in \mathbb{R}^{d_a}$，模型的目标是生成一个优化 Pass 序列 $\mathbf{y} = (y_1, y_2, \dots, y_m)$，使得按该序列依次执行编译优化后，目标程序的代码质量指标（如 IR 指令数）达到最优。形式化地，模型学习条件概率分布：

$$P(\mathbf{y} \mid \mathbf{x}, \mathbf{a}) = \prod_{t=1}^{m} P(y_t \mid y_{<t}, \mathbf{x}, \mathbf{a})$$

将该问题实例化为一个 Encoder-Decoder 架构，其中 encoder 处理 LLVM IR 文本输入，decoder 自回归地生成优化 Pass 序列，并提出一种多模态特征融合机制将程序静态特征（Autophase）注入模型。

### 3.2 模型架构

#### 3.2.1 总体架构：Passformer

Passformer 是提出的面向编译优化序列生成的 Encoder-Decoder 模型，其核心组件包括：

- **Encoder（编码器）**：加载第一阶段预训练的 InstBERT 权重（ModernBERT-base, ~149M 参数），将 LLVM IR 指令序列编码为上下文相关的隐状态表征 $\mathbf{H}^{\text{enc}} \in \mathbb{R}^{n \times d_e}$，其中 $d_e = 768$。
- **Decoder（解码器）**：采用 GPT-2 架构，从头初始化（from scratch），通过交叉注意力（Cross-Attention）机制关注 encoder 输出，自回归地生成优化 Pass token。
- **Autophase 融合模块**：将 56 维程序静态特征向量注入 encoder 与 decoder 之间的信息通路，增强模型对程序全局结构属性的感知能力。

Passformer 继承自 HuggingFace `PreTrainedModel` 与 `GenerationMixin`，完整支持 `save_pretrained`/`from_pretrained` 模型序列化以及 `generate()` 自回归解码接口，确保与 HuggingFace 训练与推理生态无缝集成。

#### 3.2.2 Encoder：InstBERT

Encoder 直接加载第一阶段预训练完成的 InstBERT 模型权重。输入 LLVM IR 经 `Inst2VecTokenizer` 分词后，得到 token 序列 $(x_1, x_2, \dots, x_n)$，经 encoder 编码后输出隐状态：

$$\mathbf{H}^{\text{enc}} = \text{InstBERT}(\mathbf{x}) \in \mathbb{R}^{n \times 768}$$

该表征同时编码了每条指令的局部操作语义和全局上下文依赖关系。在监督训练阶段，encoder 参数参与端到端微调，使预训练表征进一步适应序列生成任务的需求。

#### 3.2.3 Decoder：GPT-2 with Cross-Attention

Decoder 采用标准 GPT-2 架构并启用交叉注意力层，其详细配置如下：

| 参数 | 取值 | 说明 |
|------|------|------|
| 层数（n_layer） | 6 | Transformer 解码器层数 |
| 注意力头数（n_head） | 12 | 多头注意力 |
| 隐藏维度（n_embd） | 768 | 与 encoder 隐藏维度一致 |
| 最大位置编码（n_positions） | 512 | 覆盖最长优化序列 |
| 激活函数 | GELU (new) | - |
| Dropout（resid/embd/attn） | 0.1 | 三处均设为 0.1 |
| 交叉注意力（add_cross_attention） | True | 必须启用以接收 encoder 输出 |
| 词汇表大小（vocab_size） | 128 | 优化 Pass 词汇 + 特殊 token |

Decoder 从随机初始化开始训练，而非加载预训练权重。这是因为优化 Pass 的词汇表和序列分布与自然语言存在根本差异，预训练语言模型的先验知识反而可能产生负迁移。词汇表规模为 128，涵盖 LLVM 的全部可用优化 Pass（如 `-mem2reg`、`-instcombine`、`-gvn`、`-simplifycfg` 等）及 4 个特殊 token（`<pad>=125`、`<bos>=126`、`<eos>=127`、`<unk>`）。

在每个解码时间步 $t$，decoder 同时执行因果自注意力（masked self-attention）和对 encoder 输出的交叉注意力：

$$\mathbf{h}_t^{\text{dec}} = \text{GPT2Layer}(\mathbf{h}_{<t}^{\text{dec}}, \mathbf{H}^{\text{fused}})$$

其中 $\mathbf{H}^{\text{fused}}$ 为经过 Autophase 融合后的 encoder 表征（详见 3.3 节），decoder 通过 cross-attention 对其执行 query-key-value 注意力运算。

#### 3.2.4 OptiSeqTokenizer：优化序列分词器

Decoder 端使用专门的 `OptiSeqTokenizer` 处理优化 Pass 序列。与 Inst2VecTokenizer 基于 IR 指令预处理不同，OptiSeqTokenizer 采用空格分割（whitespace splitting）对优化序列进行分词，每个 token 对应一个 LLVM 优化 Pass flag（如 `-mem2reg`、`-instcombine`）。其词汇表以 CSV 格式存储（`vocab.txt`），包含 index-to-token 映射。编码时默认添加 `<eos>` token，解码时可选择跳过特殊 token。

### 3.3 Autophase 多模态融合机制（核心创新）

#### 3.3.1 Autophase 特征

Autophase（Haj-Ali et al., MLSys 2020）是一种 56 维的程序静态特征向量，通过对 LLVM IR 执行静态分析提取，涵盖了指令分布统计（如各类指令的出现频次）、控制流图属性（如基本块数量、分支比率）以及数据流特征（如 PHI 节点数、内存操作比例）等。Autophase 特征的优势在于提取成本极低（无需执行程序），同时能够有效刻画程序的全局结构特性——这些信息在 token 级的 IR 序列表征中往往难以直接捕获。

将 Autophase 特征引入 Passformer 的动机在于：**LLVM IR 的 token 序列表征擅长编码局部指令语义和上下文依赖，而 Autophase 特征擅长刻画程序的全局结构统计属性，二者构成互补的信息来源**。系统性地设计并对比了三种融合策略，以研究不同融合方式对序列生成质量的影响。

#### 3.3.2 方案一：Cross-Attention Only（基线, fusion_method=none）

基线方案直接使用 HuggingFace 的 `EncoderDecoderModel` 桥接 InstBERT encoder 与 GPT-2 decoder，不引入任何 Autophase 融合。Decoder 仅通过交叉注意力机制访问 encoder 的 LLVM IR 表征：

$$\mathbf{H}^{\text{fused}} = \mathbf{H}^{\text{enc}}$$

该方案作为消融实验的基准，用于衡量 Autophase 特征融合带来的增量收益。

#### 3.3.3 方案二：Additive Fusion（加性融合, fusion_method=add）

加性融合通过一个两层 MLP 将 Autophase 向量投影到与 encoder 隐状态相同的维度，然后以逐元素加法的方式广播叠加到 encoder 每个位置的隐状态上：

$$\mathbf{e}_a = \text{MLP}_{\text{add}}(\mathbf{a}) \in \mathbb{R}^{d_e}$$

$$\mathbf{H}^{\text{fused}} = \mathbf{H}^{\text{enc}} + \mathbf{e}_a$$

其中投影网络 $\text{MLP}_{\text{add}}$ 的结构为：

$$\text{MLP}_{\text{add}}: \mathbb{R}^{56} \xrightarrow{\text{Linear}} \mathbb{R}^{256} \xrightarrow{\text{LN+GELU+Dropout}} \mathbb{R}^{256} \xrightarrow{\text{Linear}} \mathbb{R}^{768} \xrightarrow{\text{LayerNorm}} \mathbb{R}^{768}$$

投影后的 Autophase 嵌入经 `unsqueeze(1)` 操作扩展为 $\mathbb{R}^{1 \times 768}$，通过 broadcasting 机制加到 encoder 输出的每个 token 位置上。这种设计等价于为每个 token 注入一个全局的程序结构偏置项（global structure bias）。

**设计优势**：参数开销极小（约 0.8M），不改变序列维度和 attention mask，保持了 encoder 原始表征空间的结构。适用于 Autophase 信息作为辅助调节信号而非主导特征的场景。

#### 3.3.4 方案三：Concatenation Fusion（拼接融合, fusion_method=concat）

拼接融合将 Autophase 特征映射为与 encoder 维度对齐的嵌入向量，与 encoder 隐状态在特征维度上逐位置拼接后，再通过一个投影网络降维到 decoder 隐藏维度。整体过程包含两个串联的 MLP：

**第一步：Autophase 特征投影**

$$\mathbf{e}_a = \text{MLP}_{\text{auto}}(\mathbf{a}) \in \mathbb{R}^{d_a'}$$

$$\text{MLP}_{\text{auto}}: \mathbb{R}^{56} \xrightarrow{\text{Linear}} \mathbb{R}^{256} \xrightarrow{\text{LN+GELU+Dropout}} \mathbb{R}^{256} \xrightarrow{\text{Linear}} \mathbb{R}^{56} \xrightarrow{\text{LayerNorm}} \mathbb{R}^{56}$$

其中 $d_a' = 56$（autophase_emb_dim，默认与 Autophase 原始维度一致）。投影后的嵌入广播到序列长度维度：$\hat{\mathbf{E}}_a \in \mathbb{R}^{n \times 56}$。

**第二步：拼接与降维投影**

$$\mathbf{C} = [\mathbf{H}^{\text{enc}} \| \hat{\mathbf{E}}_a] \in \mathbb{R}^{n \times (768 + 56)}$$

$$\mathbf{H}^{\text{fused}} = \text{MLP}_{\text{concat}}(\mathbf{C}) \in \mathbb{R}^{n \times 768}$$

$$\text{MLP}_{\text{concat}}: \mathbb{R}^{824} \xrightarrow{\text{Linear}} \mathbb{R}^{2048} \xrightarrow{\text{LN+GELU+Dropout}} \mathbb{R}^{2048} \xrightarrow{\text{Linear}} \mathbb{R}^{768} \xrightarrow{\text{LayerNorm}} \mathbb{R}^{768}$$

**设计优势**：拼接融合允许模型通过下游 MLP 学习 IR 表征与 Autophase 特征之间的非线性交互关系，信息容量显著高于加性方案。中间层维度设为 2048（约为拼接维度 824 的 2.5 倍），为特征交互提供了充足的表达空间。总参数量约 1.8M。

#### 3.3.5 三种方案的对比分析

| 维度 | Cross-Attention Only | Add Fusion | Concat Fusion |
|------|---------------------|------------|---------------|
| Autophase 使用 | 不使用 | 加性偏置 | 特征拼接+投影 |
| 融合参数量 | 0 | ~0.8M | ~1.8M |
| 融合位置 | — | encoder 输出 | encoder→decoder 信息通路 |
| 特征交互方式 | — | 线性叠加 | 非线性投影 |
| 信息容量 | 低 | 中 | 高 |
| 训练稳定性 | 高（无额外模块） | 高（残差式融合） | 中（依赖投影网络质量） |
| 适用场景 | 基线对比 | Autophase 作辅助信号 | Autophase 信息量大 |

值得注意的是，三种方案共享同一 encoder 和 decoder 架构，仅在 encoder 输出到 decoder 输入之间的融合路径上有所不同。这种可控的消融设计使得实验能够精准度量 Autophase 信息及其融合方式对序列生成质量的影响。

### 3.4 训练方案

#### 3.4.1 数据集：ga_llvm_37k

监督训练数据来自 ga_llvm_37k 数据集，该数据集通过遗传算法（Genetic Algorithm, GA）在 LLVM 优化 Pass 空间上进行搜索而构建。对于每个程序样本，遗传算法以 IR 指令数减少量为适应度函数，经过多代进化搜索得到（近似）最优的优化 Pass 序列作为标注标签。数据集共包含约 37,000 个样本，每个样本包含以下字段：

| 字段 | 说明 |
|------|------|
| LLVM_IR | 未优化的 LLVM IR 源代码 |
| Commandline | GA 搜索得到的最优优化 Pass 序列 |
| Autophase | 56 维程序静态特征向量 |
| Reward | 优化后 IR 指令数的相对减少量 |
| IrInstructionCountO0/O3/Oz | 不同优化级别下的 IR 指令数 |
| Benchmark / CpuInfo | 元数据信息 |

数据集以 HuggingFace `datasets` 格式存储，通过 `load_from_disk` 加载。Tokenization 过程通过 `create_tokenize_fn` 工厂函数构建，该函数同时接受 `Inst2VecTokenizer`（encoder 端）和 `OptiSeqTokenizer`（decoder 端）两个分词器，并支持 Autophase 特征的打包传递（`include_autophase=True`）。tokenization 采用 32 进程并行处理。数据集按 80/20 比例随机划分为训练集和测试集（seed=42）。

#### 3.4.2 训练目标

采用标准的 teacher forcing 策略进行训练。在每个时间步，decoder 以真实的前缀 token（ground-truth prefix）作为输入，预测下一个 Pass token 的概率分布，训练损失为交叉熵损失：

$$\mathcal{L}_{\text{CE}} = -\sum_{t=1}^{m} \log P(y_t \mid y_{<t}, \mathbf{x}, \mathbf{a})$$

Decoder 的输入通过 `shift_tokens_right` 函数构造：将 labels 序列右移一位，首位填入 `decoder_start_token_id`（`<bos>=126`），被标记为 -100 的位置替换为 `pad_token_id` 以排除损失计算。

#### 3.4.3 训练超参数

| 超参数 | Cross-Attention Only | Add / Concat Fusion | 说明 |
|--------|---------------------|---------------------|------|
| Encoder 最大长度 | 8192 | 1024 | 基线方案处理更长序列 |
| Decoder 最大长度 | 256 | 256 | 优化序列长度上限 |
| 训练轮数 | 20 | 20 | - |
| 单卡 batch size | 4 | 16 | 受序列长度影响 |
| 梯度累积步数 | 8 | 2 | 有效 batch size 分别为 32 |
| 学习率 | 5×10⁻⁵ | 5×10⁻⁵ | AdamW 优化器 |
| 学习率预热步数 | 500 | 500 | 线性 warmup |
| 权重衰减 | 0.01 | 0.01 | - |
| 评估策略 | 每 epoch | 每 epoch | - |
| 最优模型选择指标 | eval_loss | eval_loss | loss 越小越好 |
| 模型保存 | 每 epoch，保留最优 3 个 | 每 epoch，保留最优 3 个 | - |
| 日志记录 | 每 50 步 | 每 50 步 | TensorBoard 可视化 |

基线方案（Cross-Attention Only）采用 `encoder_maxlen=8192` 以充分利用 ModernBERT 的长序列处理能力，相应地将 batch size 降低至 4 并增大梯度累积步数至 8 以控制显存占用。Add/Concat 融合方案采用 `encoder_maxlen=1024` 和 batch size=16 的更高效配置，通过 Autophase 特征弥补较短输入序列的信息损失。

#### 3.4.4 模型初始化与权重管理

模型的初始化策略遵循以下分层设计：

1. **Encoder**：从 InstBERT 预训练检查点加载权重，端到端参与微调。
2. **Decoder**：根据 GPT-2Config 从随机初始化开始训练，Cross-Attention 层参数随机初始化（$\mathcal{N}(0, 0.02)$）。
3. **融合模块**：Linear 层以 $\mathcal{N}(0, 0.02)$ 初始化，LayerNorm 层以 weight=1、bias=0 初始化。

训练完成后，encoder tokenizer 和 decoder tokenizer 分别保存至 `encoder_tokenizer/` 和 `decoder_tokenizer/` 子目录，模型权重通过 `model.save_pretrained()` 保存，供第三阶段强化学习加载。

### 3.5 技术亮点与创新性分析

**（1）提出 Autophase 多模态融合的 Encoder-Decoder 架构。** 现有的编译优化序列预测方法大多仅依赖单一模态的程序表征（如纯文本 IR 或纯手工特征）。Passformer 首次将 LLVM IR 的深度语义表征与 Autophase 程序统计特征进行多模态融合，利用二者的互补性提升序列生成质量——前者编码指令级局部语义，后者刻画程序级全局结构。

**（2）系统性设计三种可控消融的融合策略。** 通过统一的 `fusion_method` 配置项切换融合方式（`none`/`add`/`concat`），三种方案共享相同的 encoder-decoder 架构、训练流程和超参数（除序列长度/batch size 外），为编译优化领域的多模态特征融合研究提供了严格可控的实验基线。

**（3）兼顾研究灵活性与工程可用性的模型设计。** PassformerModel 完全兼容 HuggingFace 生态：支持 `from_pretrained`/`save_pretrained` 进行模型序列化，支持 `generate()` 接口进行 beam search、sampling 等多种解码策略，支持 `Trainer` API 进行分布式训练。融合模块的配置参数（如 `fusion_intermediate_dim`、`autophase_emb_dim`、`concat_intermediate_dim`）均可通过 `PassformerConfig` 灵活调整。

**（4）面向下游强化学习的预训练-微调管线。** 监督学习阶段训练得到的 Passformer 模型权重将直接作为第三阶段 PPO 强化学习的策略网络初始化。GA 标注数据提供的是搜索空间中的近似最优解，而强化学习阶段将通过与 LLVM 编译环境的在线交互进一步突破该上界。监督预训练为策略网络提供了一个合理的初始行为分布，显著缓解了强化学习冷启动（cold-start）问题。

## 4 阶段三：编译优化强化学习（PPO）

### 4.1 动机与问题建模

#### 4.1.1 监督学习的固有局限

第二阶段的监督学习虽然使 Passformer 具备了从 LLVM IR 生成优化 Pass 序列的基本能力，但其性能上界受制于标注数据的质量。ga_llvm_37k 数据集中的标注序列来自遗传算法搜索，由于搜索空间的组合爆炸（LLVM 包含 100+ 个可用 Pass，序列长度可达数十步），GA 搜索结果仅是近似最优解而非全局最优。此外，监督学习采用 teacher forcing 训练，模型在推理时面临 exposure bias 问题——训练时始终以 ground-truth prefix 为条件，而推理时需要依赖自身的预测结果，两者之间的分布偏移会导致误差累积。

强化学习（Reinforcement Learning, RL）提供了一条突破上述瓶颈的路径：**将 Passformer 作为策略网络（policy network），通过与 LLVM 编译环境的在线交互直接优化编译后的代码质量指标**，无需依赖预先标注的"最优"序列。

#### 4.1.2 马尔可夫决策过程建模

将编译优化序列生成建模为一个马尔可夫决策过程（MDP）$\mathcal{M} = (\mathcal{S}, \mathcal{A}, \mathcal{T}, \mathcal{R}, \gamma)$：

- **状态空间 $\mathcal{S}$**：由当前 LLVM IR 程序的文本表示 $\mathbf{x}$、Autophase 特征向量 $\mathbf{a}$ 以及已生成的 Pass 序列前缀 $y_{<t}$ 共同构成。
- **动作空间 $\mathcal{A}$**：对应 OptiSeqTokenizer 词汇表中的 128 个 token（包含 ~124 个有效优化 Pass 和 4 个特殊 token）。
- **状态转移 $\mathcal{T}$**：每执行一个 Pass $y_t$，LLVM 编译环境将其应用于当前 IR，产生新的 IR 状态（确定性转移）。
- **奖励函数 $\mathcal{R}$**：每步 Pass 执行后，环境返回 IR 指令数的相对变化量作为即时奖励。
- **折扣因子 $\gamma$**：设为 0.99，鼓励模型在序列早期就选择高收益的 Pass。

策略网络 $\pi_\theta$ 即为第二阶段训练得到的 Passformer 模型，其参数 $\theta$ 在 RL 阶段继续优化。

### 4.2 PPO 算法设计

采用 Proximal Policy Optimization（PPO, Schulman et al., 2017）作为策略优化算法。相较于基础的 REINFORCE 算法，PPO 通过裁剪的替代目标（clipped surrogate objective）限制策略更新幅度，在训练稳定性和样本效率之间取得了更优的平衡。

#### 4.2.1 Rollout：多温度混合采样（关键创新）

每个训练步骤首先执行 rollout 阶段：给定一个输入样本（LLVM IR + Autophase），策略网络通过自回归采样生成 $K$ 条候选优化序列（trajectories）。提出**多温度混合采样策略**，将 $K$ 条 rollout 分配到多个不同温度下进行采样：

$$\tau_i = [0.3, 0.5, 0.7, 1.0], \quad K_i = \lfloor K / |\tau| \rfloor$$

具体地，$K$ 条 rollout 按均匀分配（余数分配给前几个温度组）分别在 4 个温度下采样。在温度 $\tau$ 下，token $y_t$ 的采样概率为：

$$P(y_t \mid y_{<t}) = \text{softmax}(\mathbf{z}_t / \tau)$$

其中 $\mathbf{z}_t$ 为 decoder 输出的 logits 向量。该策略的设计动机如下：

- **低温（$\tau = 0.3$）**：生成高置信度的 exploitation 序列，倾向于复现监督学习阶段已学到的高质量模式，提供稳定的 baseline reward。
- **中温（$\tau = 0.5, 0.7$）**：平衡探索与利用，在已知高收益区域附近进行适度变异。
- **高温（$\tau = 1.0$）**：增强 exploration，鼓励模型尝试超出监督训练分布的新颖序列，有机会发现 GA 标注数据中未覆盖的更优方案。

多温度混合采样等价于在策略分布上施加了一种结构化的探索噪声，相较于单一温度采样具有更好的覆盖性和鲁棒性。

#### 4.2.2 Per-step Reward：细粒度信用分配

与传统 RL for text generation 方法将整个序列视为一个 episode 并仅在末尾给予 reward 不同，利用 LLVM 编译环境的**可逐步执行**特性，实现了 per-step（per-pass）级别的奖励信号。

对于一条 rollout 序列 $\mathbf{y} = (y_1, y_2, \dots, y_L)$，环境依次执行每个 Pass 并记录即时奖励：

$$r_t = \mathcal{R}(s_t, y_t) = \Delta \text{IrInstructionCount}(y_t)$$

即第 $t$ 步 Pass 执行后 IR 指令数的变化量。每个 token 对应的 reward 通过独立的 LLVM CompilerGym 环境实例计算：创建环境 → reset → 逐步执行 Pass → 收集逐步 reward → 关闭环境。

这种 per-step reward 机制的核心优势在于**精准的信用分配（credit assignment）**：模型能够区分序列中哪些 Pass 贡献了正向优化（如 `-instcombine` 通常在早期产生显著收益），哪些 Pass 是冗余或有害的（如重复应用某些 Pass 可能增大 IR 体积），从而更高效地优化策略。

为提升 reward 计算效率，使用 `ThreadPoolExecutor` 对 $K$ 条 rollout 的环境评估进行多线程并行化（`num_reward_workers` 默认等于 $K$），避免了串行评估的瓶颈。

#### 4.2.3 Discounted Returns 与 Advantage 估计

获得逐步奖励后，计算折扣累积回报（discounted returns）：

$$R_t = r_t + \gamma \cdot R_{t+1} \cdot \mathbb{1}[t \text{ is valid}]$$

其中 $\gamma = 0.99$ 为折扣因子，$\mathbb{1}[\cdot]$ 为有效位置的 mask（排除 padding 位置）。折扣回报通过逆序动态规划计算。

Advantage 函数采用 **mean-rollout baseline** 策略进行方差缩减：

$$b_i = \frac{1}{K} \sum_{k=1}^{K} R_{\text{total}}^{(i,k)}$$

其中 $b_i$ 为第 $i$ 个输入样本的 $K$ 条 rollout 的平均总回报。Advantage 定义为：

$$A_t^{(i,k)} = R_t^{(i,k)} - b_i$$

最后对 advantage 进行全局标准化（zero-mean, unit-variance normalization）以稳定训练：

$$\hat{A} = \frac{A - \mu_A}{\sigma_A + \epsilon}$$

该 baseline 设计的直觉是：对于同一程序输入，高于平均回报的 rollout 应被强化，低于平均的应被抑制，从而在不引入额外 value network 的情况下实现有效的方差缩减。

#### 4.2.4 PPO Clipped Surrogate Objective

在收集完 rollout 数据后，首先计算旧策略（rollout 时的策略）下的 log-probabilities $\log \pi_{\theta_{\text{old}}}(y_t | y_{<t})$，然后执行多轮（`ppo_epochs`）梯度更新。每轮更新的目标函数为：

**（a）策略损失（Policy Loss）**：

$$r_t(\theta) = \frac{\pi_\theta(y_t | y_{<t})}{\pi_{\theta_{\text{old}}}(y_t | y_{<t})}$$

$$\mathcal{L}_{\text{policy}} = -\frac{1}{|\mathcal{V}|} \sum_{t \in \mathcal{V}} \min\left( r_t(\theta) \hat{A}_t, \ \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) \hat{A}_t \right)$$

其中 $\epsilon = 0.2$ 为裁剪系数，$\mathcal{V}$ 为有效（非 padding）位置集合。裁剪机制防止策略在单次更新中偏离旧策略过远，是 PPO 训练稳定性的核心保障。

**（b）熵奖励（Entropy Bonus）**：

$$\mathcal{L}_{\text{entropy}} = -\beta_{\text{ent}} \cdot \frac{1}{|\mathcal{V}|} \sum_{t \in \mathcal{V}} H(\pi_\theta(\cdot | y_{<t}))$$

其中 $\beta_{\text{ent}} = 0.01$，$H(\cdot)$ 为策略分布的熵。熵奖励鼓励策略保持适度的随机性，防止过早收敛到确定性策略。

**（c）KL 惩罚（可选）**：

$$\mathcal{L}_{\text{KL}} = \beta_{\text{kl}} \cdot \frac{1}{|\mathcal{V}|} \sum_{t \in \mathcal{V}} D_{\text{KL}}(\pi_{\text{ref}} \| \pi_\theta)$$

其中 $\pi_{\text{ref}}$ 为训练开始时冻结的参考模型（reference model），$\beta_{\text{kl}}$ 默认设为 0（即不启用）。当启用时，KL 惩罚约束当前策略不偏离初始监督学习策略过远，防止灾难性遗忘。参考模型在训练开始时通过 `copy.deepcopy` 复制并冻结所有参数。

**总损失**：

$$\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{policy}} + \mathcal{L}_{\text{entropy}} + \mathcal{L}_{\text{KL}}$$

#### 4.2.5 多轮 PPO 更新与自适应早停

每次 rollout 采集的数据被复用 `ppo_epochs = 4` 轮进行梯度更新，以提升样本效率。梯度裁剪（`max_grad_norm = 1.0`）防止梯度爆炸。

为防止策略在多轮更新中偏离过远，引入**近似 KL 散度早停机制**：

$$D_{\text{KL}}^{\text{approx}} = \mathbb{E}_t \left[ (r_t - 1) - \log r_t \right]$$

当 $D_{\text{KL}}^{\text{approx}} > d_{\text{target}} = 0.02$ 时，提前终止当前 rollout 的 PPO 更新。这一设计在不额外计算完整 KL 散度的情况下，为策略更新提供了一道安全阀，有效避免了 PPO 训练中偶发的策略崩溃（policy collapse）现象。

### 4.3 两种互补的训练范式

设计了两种互补的 RL 训练范式，分别面向泛化能力和精细化优化两个目标。

#### 4.3.1 Large-scale PPO：面向泛化能力的大规模训练

Large-scale PPO 旨在让模型在大量不同程序上积累优化经验，学习具有泛化能力的优化策略。

**数据组织**：训练数据为 CodeContest 数据集中的大规模 `.bc` 文件集合。全部样本按 95/5 比例随机划分为训练集和验证集（seed=42）。每个 epoch 将训练集 shuffle 后逐样本遍历，每个样本构建一个 `(llvm_ir, autophase, bc_path)` observation 用于 rollout。

**训练流程**：

1. 对每个 `.bc` 文件构建 observation（通过 `llvm_wrapper` 创建 CompilerGym 环境并 reset 获取初始 IR 与 Autophase）。
2. 执行 rollout 生成 $K=8$ 条候选序列（multi-temperature sampling）。
3. 逐步计算 per-step reward，构建 discounted returns 和 advantages。
4. 执行 PPO 多轮更新。
5. 周期性（每 `log_steps=10` 步）将训练指标写入 TensorBoard。
6. 周期性（每 `eval_steps=200` 步）在验证集上采样 50 个样本进行评估，记录 `val_reward_mean`、`val_reward_max` 和 `val_reward_geomean`。若验证集 mean reward 超过历史最优，保存 best model。
7. 周期性（每 `save_steps=500` 步）保存检查点。

**关键超参数**：

| 超参数 | 取值 | 说明 |
|--------|------|------|
| 学习率 | 5×10⁻⁶ | 低于监督阶段一个量级，RL 微调需更保守 |
| Rollout 数量 $K$ | 8 | 每个样本采样 8 条候选序列 |
| 最大生成长度 | 32 | 每条序列最多 32 个 Pass token |
| 温度组 | [0.3, 0.5, 0.7, 1.0] | 4 组温度，各分配 2 条 rollout |
| 折扣因子 $\gamma$ | 0.99 | - |
| PPO clip $\epsilon$ | 0.2 | - |
| PPO epochs | 4 | 每次 rollout 数据复用 4 轮 |
| Target KL | 0.02 | 自适应早停阈值 |
| 熵系数 | 0.01 | - |
| 训练 epoch 数 | 1 | 大数据集遍历一遍 |
| 并行 reward worker 数 | 8 | 等于 rollout 数量 |

该范式的优势在于：模型在大量异构程序上训练，学习到的策略具有较好的跨程序泛化能力。其代价是单个程序上的优化深度有限（每个样本仅训练一步）。

#### 4.3.2 Sequential RL：面向精细化优化的逐 benchmark 训练

Sequential RL 旨在让模型在每个特定 benchmark 上深度训练至收敛，追求单个程序的极致优化性能。

**数据组织**：训练数据为 cBench-v1 中的 22 个经典 benchmark 程序（如 `adpcm`、`bzip2`、`dijkstra`、`jpeg-c`、`sha` 等），以 `.bc` 文件列表形式在配置中显式指定。

**训练流程**：模型按顺序依次在每个 benchmark 上进行训练。对于每个 benchmark：

1. 创建 CompilerGym 环境，构建 observation。
2. 在该 benchmark 上最多训练 `epochs_per_benchmark=100` 轮。每轮执行一次 PPO train_step。
3. **收敛检测**：采用 patience-based 早停——若连续 `patience=50` 轮 `max_reward` 没有改善，提前切换到下一个 benchmark。
4. **阈值触发**：若某轮的 `mean_reward ≥ reward_threshold=10`，认为当前 benchmark 已充分优化，提前切换。
5. 训练完成后记录该 benchmark 的最优 reward、耗时和对应的最佳命令行（best_commandline）。

**Experience Replay 机制**：

为缓解 sequential training 中的灾难性遗忘问题，引入经验回放机制。在每完成一个新 benchmark 的训练后，从已训练过的 benchmark 池中随机采样一部分进行回放训练：

$$N_{\text{replay}} = \max(1, \lfloor |\mathcal{B}_{\text{trained}}| \times \rho \rfloor)$$

其中 $\rho$ 为回放比例（`replay_ratio`），每个被采样的 benchmark 进行 `replay_epochs` 轮回放。回放过程使用与正常训练相同的 PPO train_step，等价于在新旧任务之间进行交错训练。当前配置中 `replay_ratio=0.0`（即未启用），但框架已完整实现，可根据实验需要开启。

**关键超参数**：

| 超参数 | 取值 | 说明 |
|--------|------|------|
| 学习率 | 5×10⁻⁶ | 与 large-scale 一致 |
| Rollout 数量 $K$ | 16 | 更多 rollout 提高单样本的策略估计精度 |
| 最大生成长度 | 32 | - |
| 温度组 | [0.3, 0.5, 0.7, 1.0] | 4 组温度，各分配 4 条 rollout |
| 每 benchmark 最大轮数 | 100 | - |
| Patience | 50 | 无改善容忍轮数 |
| Reward 阈值 | 10 | 提前切换的 mean reward 阈值 |
| Replay 比例 | 0.0 | 当前未启用回放 |
| Replay 轮数 | 2 | 每次回放的 epoch 数 |

**评估指标**：训练结束后，计算所有 benchmark 的 reward 几何均值（geometric mean）作为综合评估指标。几何均值相比算术均值对异常值更鲁棒，且在不同量级的 reward 值之间提供更公平的聚合：

$$\text{GeoMean} = \exp\left(\frac{1}{|\mathcal{B}|}\sum_{b \in \mathcal{B}} \log \max(R_b, 10^{-10})\right)$$

结果以 CSV 表格形式保存（`benchmark_results.csv`），包含 benchmark 名称、最优 reward、训练耗时和对应的最佳优化命令行。

### 4.4 环境与奖励机制

#### 4.4.1 LLVM CompilerGym 环境封装

训练环境基于 CompilerGym（Cummins et al., 2022）的 LLVM 编译优化环境。通过 `llvm_wrapper` 对原始环境进行封装，支持以下功能：

- 从 `.bc` 文件直接加载 benchmark（`is_from_bc=True`）。
- 环境 reset 后返回 observation 对象，包含 `llvm_ir`（当前 IR 文本）和 `autophase`（56 维特征向量）。
- 通过 `env.step(action_id)` 逐步执行优化 Pass，返回 `(observation, reward, done, info)`。

#### 4.4.2 Per-step Reward 计算

Reward 计算在 `_eval_single_rollout` 方法中实现。对于一条 rollout 序列中的每个 token：

1. 跳过特殊 token（`<pad>`、`<bos>`、`<eos>`）。
2. 通过 `dec_tok.ids_to_tokens` 将 token ID 反解为 Pass flag（如 `-mem2reg`）。
3. 在 CompilerGym 的 action space 中查找对应的 action ID。
4. 调用 `env.step()` 执行该 Pass，获取即时 reward。
5. 若 Pass flag 无效（不在 action space 中），奖励记为 0。
6. 若环境返回 `done=True`，提前终止。

最终返回每条 rollout 的逐步 reward 向量（长度等于生成序列长度），以及总 reward 标量。

### 4.5 技术亮点与创新性分析

**（1）Per-step Reward 实现精准信用分配。** 现有的 RL for code generation 工作（如 CodeRL、RLTF 等）通常仅在序列末尾给予 episode-level reward，导致所有 token 共享相同的回报信号，难以区分各步 action 的贡献。利用 LLVM 编译环境可逐步执行的特性，实现了 token 级别的即时奖励，结合折扣回报机制为每个位置提供差异化的学习信号。这是将 RL 应用于编译优化序列生成时对环境可交互性的充分利用。

**（2）多温度混合采样平衡探索与利用。** 单一温度采样面临两难：低温导致探索不足、策略容易陷入局部最优；高温导致 reward 信号方差过大、训练不稳定。多温度混合采样在每次 rollout 中同时包含高确信度序列（稳定 baseline）和高探索性序列（发现新方案），实现了结构化的 exploration-exploitation trade-off。这种策略对于编译优化的离散组合搜索空间尤为重要，因为最优序列可能与次优序列仅有一两步之差。

**（3）双轨训练范式兼顾泛化与精细化。** Large-scale PPO 在大量异构程序上训练，学习通用优化模式（如"先 `-mem2reg` 消除内存操作、再 `-instcombine` 合并指令"等高频有效模式）；Sequential RL 在特定 benchmark 上深度训练至收敛，挖掘针对特定程序结构的专属优化策略。两种范式互为补充：前者提供良好的策略初始化，后者在此基础上进行 per-program 精细调优。

**（4）自适应 KL 早停保障训练稳定性。** PPO 的多轮更新虽然提高了样本效率，但存在过度更新导致策略崩溃的风险。近似 KL 散度早停机制以极低的计算开销（仅需 importance ratio 的简单运算）实时监控策略偏移程度，在检测到异常偏移时立即终止当前 batch 的更新。这一设计使得模型可以安全地使用较大的 `ppo_epochs`（4 轮）而不牺牲稳定性。

**（5）完整的训练基础设施与可重现性保障。** PPO 训练流程集成了 TensorBoard 实时可视化（train loss、reward mean/max、entropy、clip fraction、KL 散度等全指标）、周期性检查点保存与恢复（`--resume` 支持断点续训）、验证集评估与 best model 自动保存、benchmark 结果表导出等工程能力，确保了大规模实验的可追踪性和可重现性。

## 5 整体技术亮点总结

1. **三阶段渐进式训练范式**：预训练 → 监督学习 → 强化学习，逐步提升模型能力
2. **Autophase 多模态融合**：首次系统性研究 IR 文本表征与程序静态特征的融合策略
3. **Per-step PPO with Multi-temperature Sampling**：细粒度奖励 + 混合温度探索的强化学习框架
4. **双轨强化学习训练**：大规模泛化训练与逐 benchmark 精细化训练的互补策略
5. **端到端 HuggingFace 兼容架构**：PassformerModel 完整支持 save/load/generate 生态
